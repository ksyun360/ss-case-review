# Synthetic original-ingestion service

Status: An opt-in synthetic HTTP route and the browser call an internal server service that coordinates bounded original-file streaming with a membership-scoped PostgreSQL reference. A second service boundary reserves durable processing work after successful registration. Use synthetic data only.

`storeOriginalForReviewer(database, reviewerId, caseId, root, chunks, maximumBytes)` creates a member-scoped `receiving` attempt before consuming the byte stream. The service generates a document-version UUID on the server, writes accepted bytes through the private storage adapter, and registers the returned SHA-256 and byte length while changing the attempt to `registered` in one PostgreSQL statement. A non-member receives no attempt or reference; the service does not read the stream or create a file for that request.

The repository checks membership again while inserting the reference. If access disappears during streaming, the service removes the exact newly published version, marks the attempt `failed`, and returns no reference. An interrupted input stream leaves no published file and marks the attempt `failed`. If PostgreSQL rejects registration, the service attempts exact-file cleanup, marks the attempt `failed`, and propagates the database error. The service never treats a registration failure as successful receipt.

`storeOriginalAndQueueForReviewer` applies fixed byte, page, and extraction-version settings while reserving a durable `queued` processing row for a registered original. The service returns the original receipt only after that reservation succeeds. A missing membership returns no receipt, and an unexpected reservation failure raises `processing_reservation_failed` so a caller cannot mistake registration alone for queued processing. The registered original remains available for later reconciliation after that invariant failure.

This compensation is not an atomic transaction across PostgreSQL and the filesystem. The [persistent upload-attempt journal](upload-journal.md) records identities and states. Guarded development startup scans at most 25 attempts older than 15 minutes, atomically marks each still-receiving attempt failed, and removes its exact synthetic file before accepting requests. A process crash, power loss, storage cleanup failure, or failure after file publication can still leave an orphan until another successful startup. The storage adapter does not synchronize the containing directory. Do not acknowledge a court upload as durable or connect this service to a public route until those gaps are resolved. The service also lacks document filename/format metadata, type inspection, malware policy, audit events, resumable transfer, and court identity.

Tests use synthetic bytes, isolated PGlite databases, and test-owned temporary directories. They verify exact file bytes and reference metadata, non-member rejection before stream consumption, a journal row before byte receipt, success and failure states, membership revocation during streaming, PostgreSQL registration failure, durable processing reservation, and safe queue-reservation failure. Run `npm run verify:commit` for the full coverage, mutation, browser, and native PostgreSQL gate.
