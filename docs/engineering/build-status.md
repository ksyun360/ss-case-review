The local application-development gate passed on September 23, 2026: formatting, code/style/document lint, type checking, tests, coverage, mutation testing, production bundling, Chromium workflows, automated accessibility scans, secret scanning, dependency auditing, and license inventory checks.

The current suite passes 132 fast unit/integration tests, 8 native PostgreSQL integration tests, and 7 Chromium workflow tests. Coverage reaches 100% for lines, statements, functions, and branches across the current first-party TypeScript/TSX source. Mutation testing kills all 411 generated mutants. The dependency audit reports zero known vulnerabilities.

The record-domain package adds 18 source-span cases covering source identity, missing and wrong-case sources, exact quotations, bounds, invalid numeric positions, and Unicode offsets. These checks validate a typed internal contract; storage integrity, user authorization, extraction quality, and displayed source highlights still require implementation and integration evidence. Read the [source-span contract](source-spans.md) for trust assumptions.

The server-config package adds 11 synthetic cases for the [Gemini development settings](gemini-development.md): explicit selection, development and synthetic-data restrictions, transport, missing and blank model/key values, latest-alias rejection, and credential omission from ordinary serialization and inspection. No test reads a developer's credential or contacts Gemini. Server startup, model clients, and live provider qualification remain unimplemented.

Seven additional server-config cases now check the [synthetic development identity](case-api.md): explicit configuration, missing authorization, production and court-test refusal, court-record refusal, identity-mode enforcement, and loopback-only configuration. These checks validate configuration; no application listener starts yet. The server package adds 14 Fastify cases for reviewer-scoped lists, server-owned creation, rollback and safe diagnostics, strict inputs, browser marker/Host/Origin restrictions, bounded request bodies, malformed JSON, and no-store response headers. Three cases use real SQL through PGlite; request-rejection tests use a query spy to verify that invalid requests never reach the repository. The factory remains disconnected from the browser and court identity.

The record-storage package adds 14 [local original-storage cases](local-original-storage.md). Real temporary-file checks cover byte fidelity, private permissions, overwrite prevention, interrupted and concurrent writes, file flushing, input snapshots, original retrieval, case scope, integrity checks, path confinement, and missing files. These checks do not qualify power-loss durability, untrusted-filesystem attacks, large-document streaming, database integration, or court access controls. The browser does not invoke the adapter.

The case-repository package retains 21 [PostgreSQL metadata cases](case-repository.md) and adds one migration-wrapper unit case. An isolated in-memory PGlite engine checks atomic case creation, case/membership/reference constraints, reviewer-scoped lists and reference access, membership revocation, missing references, and parameter binding. The fast SQL tests consume the same initial migration file as the native suite.

Eight [native PostgreSQL checks](postgres-migrations.md) now exercise PostgreSQL 18.6 and node-postgres in a digest-pinned temporary Docker container: initial migration and repository round-trips, repeat runs, rollback/retry, competing migration locks, unknown history, unversioned-schema refusal, compiled-module migration discovery, and API case creation/listing with membership revocation. The API check uses Fastify request injection rather than a network listener. The harness uses generated credentials and temporary memory-backed storage; no test connects to an existing database. Deployment roles/TLS, general concurrency, and coordinated file/database recovery remain pending. Mutation testing covers first-party TypeScript, not SQL files or third-party migration internals; explicit positive and negative SQL tests supplement mutation results.
