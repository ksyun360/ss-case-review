No test reads a developer's credential or contacts Gemini. Server startup, model clients, and live provider qualification remain unimplemented.

Seven additional server-config cases check the [synthetic development identity](case-api.md): explicit configuration, missing authorization, production and court-test refusal, court-record refusal, identity-mode enforcement, and loopback-only configuration. Thirteen further server cases cover [development startup](development-server.md), fixed database settings, lifecycle cleanup, diagnostics, and the entry command. The browser creates and opens synthetic case metadata; court identity remains disconnected.

The record-storage package adds 19 [local original-storage cases](local-original-storage.md). Real temporary-file checks cover byte fidelity, private permissions, overwrite prevention, interrupted and concurrent writes, streamed byte limits, invalid budgets, file flushing, input snapshots, original retrieval, case scope, integrity checks, path confinement, and missing files. The adapter accepts bounded streams but these checks do not qualify power-loss durability, untrusted-filesystem attacks, end-to-end large-document transport, database integration, or court access controls. The browser does not invoke the adapter.

Nine [original-ingestion service cases](original-ingestion.md) connect the storage adapter to membership-filtered PostgreSQL references and the [upload-attempt journal](upload-journal.md) for synthetic data. The checks cover successful registration, denial before consuming a non-member stream, reservation before byte receipt, success and failure states, revocation during streaming, interruption, and failed database insertion with exact-file cleanup. The service has no HTTP route or crash-recovery worker; the tests do not establish atomic durability across filesystem and database boundaries.

The case-repository package has 22 [case-metadata cases](case-repository.md), 3 upload-attempt cases, and one migration-wrapper unit case. An isolated in-memory PGlite engine checks atomic case creation, case/membership/reference constraints, reviewer-scoped lists and detail/reference access, membership revocation, journal transitions, missing references, and parameter binding. The fast SQL tests consume the same ordered migration files as the native suite.

Nine [native PostgreSQL checks](postgres-migrations.md) exercise PostgreSQL 18.6 and node-postgres in a digest-pinned temporary Docker container: ordered migrations and repository round-trips, atomic journal completion, repeat runs, rollback/retry, competing migration locks, unknown history, unversioned-schema refusal, compiled-module migration discovery, and API case creation/listing with membership revocation. The API check uses Fastify request injection. A separate real-process smoke check exercised an actual loopback listener, migration, creation, listing, shutdown, and restart against a temporary memory-backed PostgreSQL container. The test stopped and removed that container. The automated harness uses generated credentials and temporary memory-backed storage; no test connects to an existing database. Deployment roles/TLS, general concurrency, and coordinated file/database recovery remain pending. Mutation testing covers first-party TypeScript, not SQL files or third-party migration internals; explicit positive and negative SQL tests supplement mutation results.
