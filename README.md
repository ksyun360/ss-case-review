# Social Security Disability Review

This project will help Western District of Texas magistrate judges and law clerks review Social Security disability appeal records and inspect cited evidence.

Current phase: Phase 4 application implementation remains in progress. The [collaborator update and completion checklist](docs/engineering/collaborator-update.md) summarize working components and remaining features. The [source-span validation contract](docs/engineering/source-spans.md) checks source identity, exact quotations, and text bounds. A [private local original-storage adapter](docs/engineering/local-original-storage.md) preserves file bytes and verifies case-scoped reads. The [PostgreSQL metadata repository](docs/engineering/case-repository.md) adds atomic case creation, membership-filtered queries, and original-file references. [Versioned migrations and native PostgreSQL checks](docs/engineering/postgres-migrations.md) verify schema creation, rollback, and migration locking. The [synthetic case API](docs/engineering/case-api.md) adds validated case creation, reviewer-scoped listing, and member-only case detail. [Guarded development startup](docs/engineering/development-server.md) runs migrations and binds a loopback listener. The browser can register selected synthetic originals when the developer explicitly enables the local route; failure recovery, document inspection, extraction, source-linked review, and court identity remain pending. The [qualification readiness checklist](docs/engineering/qualification-readiness.md) retains the required evidence and handoff gates.

Final setup reminder: Return to Phase 3 at the very end, before pilot handoff, to finish hosted CI and repository protections. Keep the existing local quality gates active throughout qualification.

Build status: [Local verification results](docs/engineering/build-status.md). Hosted CI and branch protections remain deferred; no hosted passing status applies.

Review the approved [brand and interaction specification](docs/design/brand-and-interaction.md) for the Record Review identity, palette, component dimensions, and desktop/mobile behavior. Start with the [brand board](docs/design/brand-board.svg) or the [case review workspace](docs/design/review-workspace-desktop.svg).

The application preview provides responsive home, upload-selection, saved-case, and synthetic case-detail screens. The upload screen lists document names and sizes, accepts additional selections, and removes selected files. The saved-case screen lists and creates metadata through the synthetic API when the separate API and development database run. An opt-in local route registers synthetic original bytes, and the case page lists their verified version IDs and byte counts. The preview does not inspect document contents, extract sources, or call a model.

The [Gemini development configuration helper](docs/engineering/gemini-development.md) now validates explicit server-side settings for synthetic testing. Keep credentials in the ignored root `.env`; `.env.example` contains placeholders only. The helper does not load environment files or connect the preview to Gemini. Model-client and worker integration remain pending.

Internal [document-inspection modules](docs/engineering/document-inspection.md) identify PDF/TIFF signatures, parse a synthetic PDF page count, and extract native text with page numbers, UTF-16 offsets, and parser geometry. A [synthetic processing coordinator](docs/engineering/original-processing.md) joins verified original reads, PDF admission, bounded PDF.js extraction, fixed gap reporting, and atomic source publication. A durable [document-processing journal](docs/engineering/processing-journal.md) receives every acknowledged synthetic upload, issues exclusive expiring leases, and rejects stale completion. A [serial processing scheduler](docs/engineering/processing-scheduler.md) invokes the one-job worker after guarded startup enables private original storage. A [text-source repository and API](docs/engineering/text-source-storage.md) store and retrieve synthetic page text and source identity through member-scoped SQL. The case screen inventories current sources, polls active processing work, and opens exact text with physical-page and provenance metadata. Original-page rendering and highlights, resource isolation, complete inspection, OCR, source mapping, and complete processing recovery remain pending.

Use synthetic documents only. Court sign-in, durable uploads, extraction, and case-review artifacts remain unimplemented. The preview does not support real court records or shared deployment.

With Node.js 24.21.0 and installed dependencies, run `npm run dev` and open <http://127.0.0.1:5175/>.
